# 01 — v0.2: streaming responses + embeddings task

## Context (why now)

v0.1.0 supports blocking `POST /task/{name}` — good for summaries, poor for chat. `shek_brain` and downstream services need `/task/embed` for building the vector index; `shek_brain_ui` chat page will demand streaming. Both are small additions that unlock the next milestones.

## Non-goals

- No metrics/tracing yet.
- No caching layer.
- No cross-provider work (still Ollama only).

## Design

### Streaming
`POST /task/{name}/stream` returns Server-Sent Events (`text/event-stream`).
- Payload same as `/task/{name}`.
- Uses `pydantic_ai.Agent.run_stream(...)` — pydantic-ai supports streaming natively.
- Free-form tasks stream tokens (`event: delta`, `data: {"text": "..."}`).
- Structured-output tasks stream partial JSON (`event: partial`) then a final `event: complete` with the validated object.
- Lock still held for the entire stream. Anti-thrash window updated on stream close.

### Embeddings task
Add task `embed` in `config/tasks.yaml`:
```yaml
embed:
  provider: ollama
  model: nomic-embed-text
  output_schema: EmbeddingResult
```
- `EmbeddingResult` schema already exists in `schemas.py`.
- Ollama has an OpenAI-compatible `/v1/embeddings` endpoint; `pydantic-ai` doesn't cover embeddings well — use `httpx` directly through a new `providers/ollama.py::embed(model, text)` helper.
- Route: `POST /task/embed { input: str }` returns `{ output: EmbeddingResult }`. Bypasses pydantic-ai Agent path; goes through the provider's `embed()` directly. Add a small branch in `api/routes.py` to detect the embed task shape.

## Risks

- pydantic-ai streaming API for structured outputs may not stably emit partials mid-generation. Fallback: emit only the final `complete` event; skip `partial`. Log a note in the plan.
- Ollama embedding call format may differ slightly between minor Ollama releases. Pin Ollama version in the docker image, document the compatible range in the README.
